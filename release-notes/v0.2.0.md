# PhosKinTime-Vis 0.2.0

Faster panels, pan and zoom on every scatter plot, and Firefox exports that work at journal
widths. Everything still runs on the CPU in one offline HTML file; no plotted number changes.

## Highlights

- **Faster.** On the `network` fixture, open → first panel 3.1 s → 1.0 s (Chromium) and
  4.5 s → 1.2 s (Firefox); the goodness-of-fit panel 2.6 s → 0.7 s; all files verified 4.7 s →
  1.7 s. Large dot layers are drawn by a fast canvas layer on screen (pixel-identical to the
  previous canvas drawing); exports are produced exactly as before.
- **Pan and zoom on every plot with dot marks**: Ctrl/⌘ + wheel, a toolbar, pan mode,
  double-click to reset, and the keyboard (+/−, arrow keys, 0). Facets zoom together by default
  ("link facets"). Brushing still selects in data coordinates after a zoom. List: `docs/pan-zoom.md`.
- **Export current view.** Exports show the full data range by default; the new option exports
  zoomed plots as shown and the caption states the shown axis ranges.
- **Firefox exports.** Panels that fit 85 mm in Chromium were refused in Firefox (text measured
  1 px too wide); fixed. The raw-lines PNG export went from 23.5 s to 3.4 s in Firefox.
- **Screen matches export.** GOF's overall dots now have the same 0.3 px outlines on screen as in
  the exports (SveltePlot's canvas drew them at 1.6 px).

## Supported bundle schema

Unchanged: 1.0 **DRAFT**, written in this repository. 1.x loads with a notice; 2.0 and newer are
refused.

## Known limitations

- Two performance targets are not met: the goodness-of-fit panel takes 0.7–0.8 s (target 0.5 s;
  about 0.55 s of it is laying out its four plot frames and axes), and pan/zoom frames in Firefox
  take 33–50 ms at the 95th percentile on 100,000-point plots (target 20 ms). Measurements:
  `docs/performance.md`; next steps: `docs/follow-ups.md`.
- Zooming plots with many lines (parameter parallel coordinates) is slower than zooming dots.
- A 600 dpi PNG of the goodness-of-fit panel takes about 19 s (as in 0.1.0).
- No WebAssembly is used: the profile showed the time in plot layout, not in numeric work, and
  a WebAssembly rasteriser was slower than the browsers' own canvas (decision 0006).
- From 0.1.0, still: the What-if view runs only against a mock engine (`?engine=mock`); several
  panels need data PhosKinTime does not save yet; at 85 mm panels with long parameter labels ask
  for a fix before exporting; TikZ files with many points need LuaLaTeX.
